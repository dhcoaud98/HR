# AX 사례 보고서: HR 데일리 브리핑 자동화

> 한 줄 요약: **Claude 예약 작업이 매일 아침 HR 소식을 찾아 읽고 골라 요약해 GitHub에 올립니다. 나는 10분 동안 읽고 "나에게 의미"만 생각합니다.**

## 1. 개요 및 목적

* **분석 도구/기술:**
  * **Claude 예약 작업(Scheduled Task):** 정해진 시간(매일 08:45, 한국 시간)에 사람이 없어도 클라우드에서 스스로 실행되는 AI 작업입니다. 작업 지시문(프롬프트)을 한 번 저장해 두면 매일 그대로 수행합니다.
  * **웹 검색·원문 확인(WebSearch / WebFetch):** 네 영역(HR 트렌드, 채용·취업, HR 업계, 실무 툴)을 국내·해외로 나눠 검색하고, 주요 기사는 검색 요약이 아니라 원문을 열어 확인합니다.
  * **GitHub 저장소 + Git:** 완성된 브리핑을 `briefings/YYYY/MM/YYYY-MM-DD.md`로 저장하고, 목록(`briefings/README.md`)을 갱신한 뒤 커밋·푸시합니다. 날짜별 기록이 쌓이는 개인 HR 아카이브가 됩니다.
  * **Markdown 템플릿:** 모든 소식을 "요약 2~3문장 → 나에게 의미 → 출처" 형식으로 통일합니다.
* **도입 배경 (Pain Point):**
  * **시야가 HRD에 갇혀 있음:** 기업교육 담당자로 일하다 보니 교육 소식은 잘 알지만 노무·채용·평가보상·HR 테크 소식은 놓치기 쉬웠습니다. HR 직무로 넓혀 가려면 이 영역들을 꾸준히 따라가야 합니다.
  * **정보 수집에 시간이 많이 듦:** 고용노동부 보도자료, 국내 언론, SHRM·Gartner·Josh Bersin 같은 해외 소스를 매일 돌아보려면 한 시간 넘게 걸립니다. 바쁜 날에는 건너뛰게 되고 흐름이 끊깁니다.
  * **읽어도 남지 않음:** 기사를 읽고 끝나면 내 업무·커리어와 어떻게 이어지는지 정리되지 않아 기억에 남지 않았습니다.
  * **법·제도 정보의 정확성:** 법 개정 소식은 "발표"인지 "국회 통과"인지, 언제 누구에게 적용되는지가 중요한데, 기사 제목만 보면 혼동하기 쉽습니다.

## 2. 기술 분석

* **핵심 기능 및 장점:**
  * **완전 자동 실행:** 사람이 컴퓨터를 켜지 않아도 클라우드에서 매일 정해진 시간에 실행되고, 끝나면 휴대폰 알림으로 결과를 받습니다.
  * **선별과 맥락화:** 단순히 기사를 모으는 게 아니라 영역별 1~2개, 총 5~8개만 고르고, 각 소식마다 "HRD에서 HR로 넓히는 사람에게 어떤 의미인지"를 한두 문장으로 붙입니다.
  * **이전 브리핑과의 연결:** 최근 브리핑 2~3개를 먼저 읽어 같은 소식을 반복하지 않고, "지난 브리핑의 ○○와 함께 보면" 식으로 흐름을 이어 줍니다.
  * **신뢰도 표시 규칙:** 법 개정은 시행일·적용 대상·국회 통과 여부를 반드시 적고(⚠️ 제도 상태), 업체 자체 조사나 전망치는 따로 표시합니다(ℹ️ 확인 정도). 없는 소식은 지어내지 않고 "눈에 띄는 소식 없음"이라고 씁니다.
  * **기록이 자산이 됨:** Git 커밋으로 날짜별 기록이 남아, 나중에 "한 달 동안 노무 쪽에서 무슨 일이 있었나"를 한 번에 돌아볼 수 있습니다.
  * **설정 변경이 쉬움:** 영역·검색 소스·형식을 바꾸고 싶으면 코드가 아니라 작업 지시문(한국어 문장)만 고치면 됩니다.
* **한계점 (보안, 비용 등):**
  * **보안·공개 범위:** 이 저장소는 **공개(public) 저장소**입니다. 공개된 뉴스만 다루기 때문에 문제는 없지만, 회사 내부 자료나 직원 정보를 브리핑에 넣으면 그대로 외부에 공개됩니다. 사내 적용 시에는 비공개 저장소나 사내 문서 도구로 옮겨야 합니다.
  * **자동 푸시의 위험:** 예약 작업이 검토 없이 main 브랜치에 바로 푸시합니다. 잘못된 내용도 그대로 올라갈 수 있으므로, 수정 금지 폴더(README, hr-analytics, hr-news)를 지시문에 명시해 범위를 제한했습니다.
  * **정확성(환각) 위험:** AI가 기사를 잘못 요약하거나 날짜를 착각할 수 있습니다. 원문 확인(WebFetch)과 출처 링크로 줄이고 있지만, **법·제도 내용은 반드시 고용노동부 원문으로 다시 확인**해야 합니다.
  * **수집 범위의 한계:** 일부 사이트(예: Gartner 보도자료 원문, 유료 기사)는 열리지 않아 2차 보도에 의존할 때가 있습니다. 웹 검색이 놓친 소식은 브리핑에도 없습니다.
  * **저작권:** 원문을 옮기지 않고 자기 말로 요약하며, 인용은 한 구절(15단어 미만)로 제한합니다.
  * **비용:** 별도 서버·도메인 비용은 없고, Claude 구독 요금제의 사용량 안에서 실행됩니다. 다만 매일 여러 번 검색·원문 확인을 하므로 사용량을 꽤 쓰고, 요금제 한도에 따라 실행이 제한될 수 있습니다.

## 3. 업무 적용 (AX Workflow)

* **적용 대상:**
  * **1차(현재):** 나 자신. HRD 담당자의 HR 전반 학습과 HR 직무 커리어 준비
  * **2차(확장 가능):** 인사팀·교육팀 동료와의 주간 HR 이슈 공유, 사내 리더 대상 "이번 주 노무·제도 변화" 안내, 신규 HR 담당자 온보딩 읽기 자료
* **Before & After:**
  * **Before:**
    1. 출근 후 포털·언론사·고용노동부 사이트를 돌며 HR 기사를 찾음 (영역마다 따로 검색)
    2. 해외 소식(SHRM, Gartner 등)은 영어라 부담스러워 자주 건너뜀
    3. 기사를 읽어도 메모 없이 끝나거나, 북마크만 쌓이고 다시 보지 않음
    4. 법 개정 기사는 "발표"와 "시행"을 헷갈린 채 넘어감
    5. 바쁜 날은 아예 못 하고, 결국 HRD 소식 위주로만 보게 됨
  * **After:**
    1. **08:45** Claude 예약 작업이 자동 실행 → 네 영역 × 국내·해외 검색 → 주요 기사 원문 확인
    2. 5~8개 소식을 골라 같은 형식으로 요약하고, 법·제도는 시행일·대상·통과 여부를 표시
    3. GitHub `briefings/`에 저장하고 목록 갱신 → 휴대폰으로 완료 알림
    4. **출근길 10분** 브리핑을 읽고, "→ 나에게 의미" 중 마음에 드는 것 하나를 골라 내 생각을 더함
    5. 금요일에는 한 주 브리핑을 훑어보며 반복해서 나온 키워드를 정리

```
[Before]  검색(30분) → 읽기(30분) → 정리(20분, 자주 생략)        = 약 60~80분/일, 불규칙
[After]   Claude 자동 수집·선별·요약(0분) → 읽고 생각 더하기(10~15분) = 약 10~15분/일, 매일
```

## 4. 기대효과 및 실행 과제

* **기대효과 (시간/비용 절감):**
  * **시간:** 하루 약 60~80분 걸리던 수집·정리가 10~15분 읽기로 줄어듭니다. 영업일 20일 기준 **한 달 약 15~20시간 절약**을 기대합니다. (직접 해 보며 잡은 추정치입니다.)
  * **비용:** 추가 유료 뉴스 구독이나 서버 없이, 이미 쓰는 Claude 요금제 안에서 운영합니다.
  * **학습 효과:** 매일 빠짐없이 네 영역을 접하면서, HRD 바깥의 HR 용어와 제도(퇴직급여, 구인배수, 직무급, ATS 등)에 익숙해집니다.
  * **커리어 자산:** 날짜별 브리핑과 "나에게 의미" 기록이 쌓여, HR 직무 면접에서 "최근 HR 이슈를 어떻게 보는가"에 근거를 들어 답할 수 있습니다.
  * **정확성 습관:** "발표 / 국회 통과 / 시행"을 구분해 읽는 습관이 생겨, 노무 정보를 다룰 때 실수를 줄입니다.
* **실행 과제:**
  1. **주간 회고 자동화:** 금요일 브리핑에 "이번 주 키워드 3개와 다음 주 볼 일정(국회 본회의, 통계 발표일)"을 추가하기
  2. **품질 점검:** 한 달에 한 번, 브리핑 몇 개를 골라 출처 링크와 원문이 맞는지 직접 확인하고 지시문을 다듬기
  3. **공부노트 연결:** 브리핑에서 고른 소식을 `hr-news`의 `save_reading`으로 공부노트에 저장해, 읽기와 기록을 한 흐름으로 묶기
  4. **영역 확장:** 학습 로드맵의 빈칸(조직문화·직원 경험, 평가·보상 실습)에 맞춰 검색 영역과 실습 폴더를 늘리기
  5. **사내 적용 검토:** 팀 공유용으로 쓰려면 비공개 저장소나 사내 메신저로 옮기고, 사내 데이터는 절대 넣지 않는다는 규칙을 먼저 정하기
